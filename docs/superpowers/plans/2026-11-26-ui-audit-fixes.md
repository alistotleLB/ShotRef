## Global Constraints

These bind every task.

- **Who it is for.** Ali's words: "this app is meant to be used by the average person, so it should be clear, helpful, and easily understandable. It should guide the user where guidance is needed. It should not over-complicate things." When two ways satisfy the task, pick the one a first-time user understands faster.
- **Design only.** Change how the app looks, reads and guides. Do not change what a feature does, the project file format, autosave, undo or export output, except where a task says so in words.
- Read `CLAUDE.md` first. Its rules hold: one offline HTML file, no network, no `blob:` URLs, `localStorage` in try/catch, no `alert/confirm/prompt`, both environments keep working, the Design rules section.
- **Text sizes:** three only: 12 px (small), 13 px (normal), 15 px (heading). No in-between sizes. (Task 1 moves the old 11.5 px to 12 px.)
- **Colour meaning after Task 1.** Orange `#ff9a3c` is for: the one main button of a step, the shot camera and its keys, the item selected in the scene (outline, label, list-row bar), the playhead time, the step disc and tab underline, sliders and tick boxes. "This setting is chosen" is a light grey ring `#c3c8cf`, never orange. Green `#59d18a` means success, red `#ff7a7a` means a problem.
- **Words:** plain English, sentence case, real operator terms (dolly, truck). One name per thing.
- **Locked, do not touch:** the picture tiles' art (`src/tile-pics.js`), the hands-on tour stays switched off, `PROJECT.md`, the version number, anything under `release/`. No push, no publish.
- **Line endings:** LF only in every file you touch (`tr -cd '\r' < file | wc -c` must print 0).
- **Tests.** `npm run build`, then the matching checks with `node test/smoke.cjs --only <part of name>` while you work. A check whose expectation the task changes on purpose is updated, never deleted. Each new behaviour gets a new `check(...)` appended at the end of `test/smoke.cjs` (desktop behaviour: `test/desktop.cjs`). Run the full `npm run build && npm test` once before you commit (about 12 minutes; if a timing-sensitive check fails, re-run that one alone before concluding). Run `npm run test:desktop` too if you touched `electron/`, `src/platform.js` or anything that differs on the desktop; afterwards `tasklist | grep -ci electron` must print 0.
- **Look at it.** After a visible change run `npm run visual` and open the pictures in `dist/visual/` that show what you changed. Check the small window too (1100 x 700, picture `08-narrow`).
- **Commit** on the current branch when the task is done, message ending with the line `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- If `CLAUDE.md` describes something your task changes (tab names, where a control lives), update those lines in `CLAUDE.md`.

8. **One-line hint (finding 3.4).** `#hint` never wraps: `white-space:nowrap; overflow:hidden; text-overflow:ellipsis`, max width 60% of the view as now. Shorten the hint texts to at most four tips each. Nothing selected, editor or top view: `Drag: orbit · Right-drag: pan · Scroll: zoom · Right-click: options`. Then seven rows of two: Dolly in | Dolly out, Orbit left | Orbit right, Truck left | Truck right, Crane up | Crane down, Pan left | Pan right, Tilt up | Tilt down, Zoom in | Dolly zoom. 10. **Name labels do not overlap (finding 17).** In the 3D view, when two name labels (`.lbl3d`) would overlap on screen, the later one moves up by its own height plus 2 px (repeat until clear, at most 6 steps). The selected item's label stays where it is; others move around it.

## Task 3: Guidance for a first-time user

Findings 2, 5, 15, 18. Files: `src/main.js`, `src/index.html`, `test/smoke.cjs`.

If the viewpoint ends up inside any item's box, or a person's middle is hidden behind another item from there, raise the viewpoint by 2 m and pull back 2 m and try again (at most 8 tries). The top view centres on the same middle. An empty stage keeps today's default view. ## Task 4: Messages, names, tooltips and symbols

Findings 7, 14, 16. Files: `src/main.js`, `src/index.html`, `src/sky.js`, `src/tour-copy.js`, `test/smoke.cjs`.

1. **Three kinds of message (finding 7).** `toast(msg, ms, kind)` with kind `'info'` (default, looks as now), `'ok'` (a green tick `#59d18a` before the text) or `'bad'` (a 3 px red left edge `#ff7a7a`; stays 8 seconds or until clicked; can be clicked to dismiss). Go through every `toast(` call (about 146) and set the kind: `'bad'` for anything that failed, was refused or needs the user to act to get what they asked for ("Could not…", "This isn't a ShotRef project…", "… is behind the camera", "Select something first…", a walk that runs past the end of the shot, storage warnings); `'ok'` for a finished save, export or copy ("Saved …", "… copied", "Project opened"); everything else stays info.    - First-run tour question (`src/tour-copy.js`): where it says the tour is "in the Help menu", the web and claude.ai pages say `It's always under the gear button, top right.`; the Windows app keeps "in the Help menu".
